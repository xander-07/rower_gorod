# Архитектура проекта

## Цель

Собрать устойчивую автономную систему для Waveshare UGV02 на Raspberry Pi 5, которая сможет локализоваться на небольшом городском полигоне, обнаруживать дорожные знаки и выполнять маршрут с учётом ПДД.

## Базовый принцип

Не строим один большой Python-скрипт. Каждая подсистема работает отдельным ROS 2 узлом, а `mission_manager` связывает их на уровне логики задания.

## Поток данных

```text
LDROBOT STL-19P
      |
      v
   /scan ---------------------> localization / Nav2
                                   |
UGV02 ESP32 <---- UART ---- ugv_base_bridge ----> /cmd_vel
      |                            |
      |                            +-------------> /odom
      |
      +---- состояние базы

Camera ---> sign_detector ---> /traffic_signs ---> mission_manager
                                                  |
                                                  v
                                     goals / restrictions for Nav2
```

## Подсистемы

### 1. ugv_base_bridge

Назначение:

- принимать ROS 2 `geometry_msgs/Twist` из `/cmd_vel`;
- преобразовывать линейную/угловую скорость в команды левой и правой сторон UGV02;
- передавать JSON-команды нижнему ESP32 по UART;
- принимать телеметрию базы;
- публиковать одометрию, если необходимые данные доступны от контроллера;
- реализовать аварийный stop при потере команд.

Официальный Waveshare-код для Raspberry Pi 5 использует UART `/dev/ttyAMA0` со скоростью 115200 бод. Команда прямого управления скоростью сторон имеет вид `{"T":1,"L":...,"R":...}`.

### 2. ldlidar

Назначение:

- запуск драйвера LDROBOT;
- публикация `sensor_msgs/LaserScan` в `/scan`;
- TF `base_link -> base_laser`;
- фильтрация зоны, перекрытой корпусом робота, если это понадобится.

Физическое положение лидара относительно центра робота необходимо измерить на установленной платформе и записать в параметры/URDF, а не подбирать визуально.

### 3. localization_navigation

Предполагаемый стек:

- `slam_toolbox` для построения карты во время подготовки;
- `nav2_map_server` + AMCL для соревновательной попытки на сохранённой карте;
- Nav2 costmaps для препятствий;
- ограниченные скорости из-за малого полигона и близко расположенных зданий.

Полигон всего 4 × 4 м, поэтому точность TF, геометрии робота и параметров лидара важнее высокой максимальной скорости.

### 4. sign_detector

Задачи:

- движение прямо;
- движение налево;
- движение направо;
- запрет поворота налево;
- запрет поворота направо;
- остановка;
- парковка;
- опасный объект.

Узел должен публиковать не только класс знака, но и уверенность, время обнаружения и по возможности положение/дистанцию относительно робота. Решение о манёвре нельзя принимать по одному кадру — потребуется подтверждение несколькими последовательными наблюдениями.

### 5. mission_manager

Состояния миссии планируются примерно так:

```text
WAIT_START
  -> LOCALIZE
  -> DRIVE
  -> APPROACH_INTERSECTION
  -> APPLY_TRAFFIC_RULE
  -> DRIVE
  -> APPROACH_BUS_STOP
  -> STOP_2_SECONDS
  -> DRIVE
  -> APPROACH_PARKING
  -> FINISH
```

`mission_manager` должен хранить актуальные ограничения перекрёстка и не позволять Nav2 выбрать запрещённый манёвр.

## Первые технические этапы

1. Проверить ручное управление UGV02 через ROS 2 `/cmd_vel`.
2. Поднять STL-19P и проверить стабильный `/scan` в RViz2.
3. Зафиксировать правильную TF-геометрию базы и лидара.
4. Получить устойчивую одометрию.
5. Построить тестовую карту и добиться повторяемой локализации.
6. Запустить Nav2 без распознавания знаков.
7. Добавить распознавание знаков.
8. Добавить `mission_manager` и правила перекрёстков.
9. Отдельно отладать остановку на 2 секунды и парковку.
