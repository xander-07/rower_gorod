# Платформа Raspberry Pi 5 — текущее состояние и план

Дата диагностики: 2026-09-12.

## Текущее состояние Raspberry Pi 5

По выводу с робота:

- ОС: Debian GNU/Linux 12 (bookworm).
- Raspberry Pi: RPi 5, 8 GB.
- ROS 2 в текущей системе не установлен (`ROS_DISTRO` пустой).
- UART базы доступен как `/dev/serial0 -> /dev/ttyAMA0`.
- USB-UART доступен как `/dev/ttyUSB0`.
- USB-UART определяется как Silicon Labs CP210x (`10c4:ea60`).
- На текущий момент это единственный USB serial device, поэтому при подключённом STL-19P он является наиболее вероятным портом лидара.

## База Waveshare UGV02

Штатный Raspberry Pi код Waveshare работает с нижним ESP32 через GPIO UART 115200 бод. Для Raspberry Pi 5 в `waveshareteam/ugv_rpi/base_ctrl.py` используется `/dev/ttyAMA0`.

Текущая ROS-версия прошивки нижнего контроллера Waveshare содержит нативную команду линейной/угловой скорости:

```json
{"T":13,"X":0.1,"Z":0.3}
```

где `X` задаётся в м/с, а `Z` — в рад/с. Перед использованием этой команды на конкретном роботе нужно подтвердить, что установленная на ESP32 версия прошивки её поддерживает. До этой проверки мост ROS 2 не должен полагаться на команду `T=13` без fallback.

## LDROBOT STL-19P

STL-19P использует односторонний UART поток со скоростью 230400 бод, 8 бит, 1 стоп-бит, без parity и flow control. Формат пакета совместим с семейством LD19/STL-19P.

Для безопасной проверки добавлен скрипт:

```bash
python3 scripts/stl19p_probe.py --port /dev/ttyUSB0 --frames 10
```

Скрипт только читает порт и ничего не отправляет в лидар.

### Конфликт со штатным `ugv_rpi/app.py`

В текущем `waveshareteam/ugv_rpi/base_ctrl.py` при запуске приложения автоматически открывается первый `/dev/ttyUSB*` на 115200 бод как порт дополнительного датчика. Если STL-19P подключён через CP210x как `/dev/ttyUSB0`, штатный `app.py` может одновременно читать этот же порт и мешать проверке лидара.

Перед запуском `stl19p_probe.py` нужно проверить и временно остановить штатное приложение:

```bash
pgrep -af 'ugv_rpi/app.py'
pkill -f 'ugv_rpi/app.py' || true
```

После этого можно запускать probe. Штатный `app.py` обычно запускается при загрузке через crontab Waveshare, поэтому после перезагрузки он появится снова.

## Важный момент по ROS 2

Для ROS 2 Jazzy основной Tier 1 Linux — Ubuntu 24.04 (Noble), включая arm64. Debian Bookworm в матрице Jazzy не является Tier 1 платформой для Raspberry Pi arm64. Поэтому для соревновательного робота основной рекомендуемый вариант — Ubuntu 24.04 arm64 на Raspberry Pi 5, а текущую Debian-карту Waveshare желательно сохранить как резервную.

Альтернативный вариант — оставить Debian 12 на хосте и запускать ROS 2 Jazzy/Nav2 в Ubuntu 24.04 arm64 контейнере с пробросом `/dev/ttyAMA0` и `/dev/ttyUSB0`. Это сохраняет штатную систему Waveshare, но усложняет запуск RViz, камеры и сервисов.
