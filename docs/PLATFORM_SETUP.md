# Платформа Raspberry Pi 5 — текущее состояние и план

Дата диагностики: 2026-09-12.

## Текущее состояние Raspberry Pi 5

По выводу с робота:

- ОС: Debian GNU/Linux 12 (bookworm).
- Raspberry Pi: RPi 5, 8 GB.
- ROS 2 в текущей системе не установлен (`ROS_DISTRO` пустой).
- UART базы доступен как `/dev/serial0 -> /dev/ttyAMA0`.
- USB-UART доступен как `/dev/ttyUSB0`.
- USB-UART определяется как Silicon Labs CP210x (`10c4:ea60`).
- При подключённом STL-19P именно `/dev/ttyUSB0` подтверждён как его порт.

## База Waveshare UGV02

Штатный Raspberry Pi код Waveshare работает с нижним ESP32 через GPIO UART 115200 бод. Для Raspberry Pi 5 в `waveshareteam/ugv_rpi/base_ctrl.py` используется `/dev/ttyAMA0`.

Текущая ROS-версия прошивки нижнего контроллера Waveshare содержит нативную команду линейной/угловой скорости:

```json
{"T":13,"X":0.1,"Z":0.3}
```

где `X` задаётся в м/с, а `Z` — в рад/с. Перед использованием этой команды на конкретном роботе нужно подтвердить, что установленная на ESP32 версия прошивки её поддерживает. До этой проверки мост ROS 2 не должен полагаться на команду `T=13` без fallback.

## LDROBOT STL-19P

STL-19P использует односторонний UART поток со скоростью 230400 бод. На данном роботе поток успешно подтверждён через CP210x `/dev/ttyUSB0`.

Первый тест 2026-09-12:

- получено 20 последовательных пакетов по 47 байт;
- заголовок пакета: `0x54 0x2C`;
- 12 измерительных точек на пакет;
- скорость вращения в пакетах: около `3567 deg/s`, то есть примерно `9.91 Hz`;
- углы идут последовательно по кругу;
- реальные измеренные расстояния присутствуют (примерно от 0.34 м до 13.7 м в данном тесте);
- 20 пакетов были получены примерно за 0.05 с.

Это подтверждает корректность порта, baudrate и базового формата данных STL-19P/LD19-family.

Для безопасной проверки используется:

```bash
python3 scripts/stl19p_probe.py --port /dev/ttyUSB0 --frames 20
```

Скрипт только читает порт и ничего не отправляет в лидар. После первого успешного теста скрипт дополнен проверкой CRC-8 каждого пакета и выводом частоты вращения в Hz.

### Конфликт со штатным `ugv_rpi/app.py`

Штатный `ugv_rpi/app.py` автоматически открывает первый `/dev/ttyUSB*` как дополнительный датчик и поэтому конфликтует с STL-19P.

На данной Raspberry Pi приложение запускается не через crontab, а через пользовательский systemd unit:

```text
/home/rower/.config/systemd/user/ugv-app.service
```

В unit установлен:

```ini
Restart=always
```

из-за чего простой `kill` или `pkill` приводит к автоматическому перезапуску приложения.

Для работ с лидаром сервис был остановлен принудительно и отключён из автозапуска:

```bash
systemctl --user kill --kill-who=all --signal=SIGKILL ugv-app.service
systemctl --user disable ugv-app.service
```

После этого `/dev/ttyUSB0` освобождён. `ugv-jupyter.service` можно оставлять включённым.

Вернуть штатное приложение можно командами:

```bash
systemctl --user enable ugv-app.service
systemctl --user start ugv-app.service
```

Но в итоговой конфигурации проекта `rower_gorod` штатное приложение не должно конкурировать с ROS 2 узлом за последовательные порты.

## Важный момент по ROS 2

Для ROS 2 Jazzy основной рекомендуемый вариант проекта — Ubuntu 24.04 arm64 на Raspberry Pi 5. Текущую Debian-карту Waveshare желательно сохранить как резервную рабочую карту.

Альтернативный вариант — оставить Debian 12 на хосте и запускать ROS 2 Jazzy/Nav2 в Ubuntu 24.04 arm64 контейнере с пробросом `/dev/ttyAMA0` и `/dev/ttyUSB0`. Это сохраняет штатную систему Waveshare, но усложняет запуск RViz, камеры и сервисов.

## Следующий этап

1. Запустить обновлённый `stl19p_probe.py` и подтвердить CRC пакетов.
2. Зафиксировать постоянное имя USB-UART лидара через `/dev/serial/by-id` или udev-правило.
3. Определить вариант ROS 2: Ubuntu 24.04 arm64 (предпочтительно) или контейнер на Debian 12.
4. Создать ROS 2 узел лидара с публикацией `/scan`.
5. Создать `rower_base_bridge` и проверить управление базой на малой скорости.
6. Подключить TF, одометрию, SLAM Toolbox и Nav2.
