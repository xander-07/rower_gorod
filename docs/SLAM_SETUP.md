# SLAM Toolbox setup

The physical robot runs ROS 2 Jazzy inside the project Docker image on Debian 12. The mapping stack uses:

```text
/scan -> slam_toolbox
/odom + odom->base_link -> slam_toolbox
base_link->laser -> robot_state_publisher
slam_toolbox -> map + map->odom
ROS topics/TF -> foxglove_bridge -> WebSocket :8765 -> Windows browser
```

## Rebuild Docker image after Foxglove changes

Foxglove Bridge is installed inside the project ROS image. After pulling a Dockerfile change, rebuild the image from the Debian host:

```bash
cd ~/rower_gorod
git pull
./scripts/build_ros2_docker.sh
```

## Build workspace package

From the Debian host:

```bash
cd ~/rower_gorod

./scripts/run_ros2_docker.sh \
  colcon build \
  --symlink-install \
  --packages-select rower_navigation
```

## Safe startup check

Start the complete robot + SLAM stack with physical motion disabled:

```bash
cd ~/rower_gorod

./scripts/run_ros2_docker.sh \
  ros2 launch rower_navigation mapping.launch.py \
  enable_motion:=false
```

`mapping.launch.py` starts Foxglove Bridge by default on TCP port `8765`, bound to `0.0.0.0` so a computer on the same LAN can connect.

Expected graph:

```text
map -> odom -> base_link -> laser
```

Useful checks from another SSH terminal:

```bash
cd ~/rower_gorod
./scripts/run_ros2_docker.sh ros2 lifecycle get /slam_toolbox
```

```bash
cd ~/rower_gorod
./scripts/run_ros2_docker.sh ros2 topic hz /scan
```

```bash
cd ~/rower_gorod
./scripts/run_ros2_docker.sh ros2 topic hz /odom
```

```bash
cd ~/rower_gorod
./scripts/run_ros2_docker.sh ros2 topic hz /map
```

```bash
cd ~/rower_gorod
./scripts/run_ros2_docker.sh ros2 run tf2_ros tf2_echo map laser
```

```bash
cd ~/rower_gorod
./scripts/run_ros2_docker.sh ros2 node list | grep foxglove
```

`/scan` should be close to 10 Hz, `/odom` should be present continuously, `/map` should be near 1 Hz, SLAM Toolbox should be `active`, and `tf2_echo map laser` should resolve through `map -> odom -> base_link -> laser`.

## Windows browser visualization with Foxglove

The Windows computer and the robot must be on the same network.

Find the robot IPv4 address on the Raspberry Pi host:

```bash
hostname -I
```

Use the address belonging to the LAN/Wi-Fi interface, for example `192.168.1.50`.

On Windows open Foxglove in the browser, choose `Open connection`, select `Foxglove WebSocket`, and connect to:

```text
ws://ROBOT_IP:8765
```

Example:

```text
ws://192.168.1.50:8765
```

For the first mapping layout, add a `3D` panel and set the fixed frame to `map`. Display at least:

```text
/map
/scan
/tf
/tf_static
```

`/map` shows the OccupancyGrid generated by SLAM Toolbox; `/scan` lets you compare the current LiDAR returns with the map; TF shows the robot pose in the map.

Do not expose port `8765` to the public Internet. It is intended for the local robot network during development.

Foxglove can be disabled for a launch with:

```bash
cd ~/rower_gorod

./scripts/run_ros2_docker.sh \
  ros2 launch rower_navigation mapping.launch.py \
  enable_motion:=false \
  enable_foxglove:=false
```

The WebSocket port can also be changed, for example:

```text
foxglove_port:=8766
```

## Mapping with motion enabled

Only after the safe startup check passes, stop the previous launch and restart explicitly with drive motion enabled:

```bash
cd ~/rower_gorod

./scripts/run_ros2_docker.sh \
  ros2 launch rower_navigation mapping.launch.py \
  enable_motion:=true
```

Use slow manual motion. For the first mapping run, prefer straight segments and in-place turns because those modes have been calibrated. Moving arcs are not yet separately calibrated.

A keyboard teleop can be started from another SSH terminal:

```bash
cd ~/rower_gorod

./scripts/run_ros2_docker.sh \
  ros2 run teleop_twist_keyboard teleop_twist_keyboard \
  --ros-args \
  -p speed:=0.06 \
  -p turn:=0.40
```

Keep the area clear and be ready to stop the mapping launch with Ctrl+C if the chassis behaves unexpectedly.

For the first pass, use a stop-turn-go pattern rather than long moving arcs:

```text
straight -> stop -> in-place turn -> stop -> straight
```

Watch the Foxglove map while driving. If walls duplicate, rotate, or drift badly, stop and diagnose before continuing the map.

## Save a map

When the map is clean and the robot has revisited enough of the environment for loop closure, save it into the repository:

```bash
cd ~/rower_gorod

./scripts/run_ros2_docker.sh \
  ros2 run nav2_map_server map_saver_cli \
  -f /workspace/rower_gorod/maps/arena
```

This produces `maps/arena.yaml` and `maps/arena.pgm`. Commit both files after visually validating the saved map.
